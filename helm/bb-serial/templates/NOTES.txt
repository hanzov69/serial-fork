1. Check that both containers are running:

   kubectl get pods -l app.kubernetes.io/instance={{ .Release.Name }} -n {{ .Release.Namespace }}

   You should see 2/2 containers Ready.

2. View logs:

   kubectl logs -l app.kubernetes.io/instance={{ .Release.Name }} -c web -n {{ .Release.Namespace }}
   kubectl logs -l app.kubernetes.io/instance={{ .Release.Name }} -c bot -n {{ .Release.Namespace }}

{{- if .Values.ingress.enabled }}
3. The web app is available at:

   http{{ if .Values.ingress.tls.enabled }}s{{ end }}://{{ .Values.ingress.host }}

{{- else }}
3. Access the web app via port-forward:

   kubectl port-forward svc/{{ include "bb-serial.fullname" . }} 8000:{{ .Values.service.port }} -n {{ .Release.Namespace }}

   Then open http://localhost:8000

{{- end }}

IMPORTANT — Discord slash commands:
  After your first deploy, run a one-time upgrade with syncCommands=true
  to register slash commands with Discord, then flip it back to false:

    helm upgrade {{ .Release.Name }} ./helm/bb-serial \
      --set config.syncCommands=true --reuse-values
    # wait ~30s, then:
    helm upgrade {{ .Release.Name }} ./helm/bb-serial \
      --set config.syncCommands=false --reuse-values

IMPORTANT — OAuth2 redirect URI:
  Register this URL in the Discord Developer Portal → OAuth2 → Redirects:

    {{ .Values.web.baseUrl }}/auth/callback
